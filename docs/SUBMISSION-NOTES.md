```

Harness Mobile 是开源 AI 编码助手 Harness 的移动端客户端，
不是独立的内容服务。它本身不提供 AI 能力，也不内置模型与服务器，
仅用于让用户通过手机访问「用户自己部署」的 Harness 服务。


应用首页需要用户填写自己服务器的地址（或扫码获取），这是设计如此，
而非功能缺陷。因此审核老师首次打开时看到的是"输入地址 / 扫码连接"页面。


首次启动时会弹出隐私政策摘要（隐私政策 / 用户协议入口均可点开查看），
点"同意"后方可使用；选择仅保存在设备本地。首页页脚也有"隐私政策 / 用户协议"入口。


聊天界面顶栏常驻"AI 生成内容"徽标：会话内容由用户自部署的服务生成，
本应用仅负责展示，不提供 AI 生成服务。


演示录屏已上传到自测文件（HarmonyOS 设备录制，从启动应用开始）：
首启隐私弹窗 → 扫码配置 → 连接成功 → 进入会话 → 发送消息，约 60 秒。


应用无自有账号体系，不需要注册登录。
用户仅可选填自己服务器的访问令牌，用于连接其自建服务。
本应用不提供 AI 生成服务，因此不设基于手机号/身份证的实名认证入口；
访问控制由用户自己的服务器令牌实现。


1. ohos.permission.INTERNET
用途：访问用户指定的 Harness 服务地址。
必要性：应用核心功能就是连接并展示该服务界面，无此权限无法使用。

用户设备与其自己指定的服务器之间。

- 用户的服务器地址与访问令牌仅保存在设备本地（应用私有存储）。
```

## English version

```
[What this app is]
Harness Mobile is a mobile client for Harness, an open-source AI coding
assistant. The app itself provides no AI capability, hosts no server and
ships no model; it only lets a user reach a Harness instance that the user
deploys themselves.

[Why the first screen asks for an address]
The home screen intentionally asks for the user's own server URL (or a QR code).
A reviewer opening the app for the first time therefore sees a configuration
screen by design, not because functionality is missing.

[First-launch privacy prompt]
On first launch the app shows a privacy-policy summary (with links to the full
privacy policy and user agreement) and asks for consent before use. The choice
is stored on-device only. The same links are in the home-page footer.

[AI content label]
A persistent "AI 生成内容" (AI-generated content) badge sits in the chat
top bar: conversation content is generated by the user's own deployed
service; the app only renders it and provides no AI generation service.

[How to evaluate the core feature]
A demo video is attached to this submission (recorded on a HarmonyOS device,
starting from app launch): privacy prompt -> scan -> connect -> open session
-> send message, about 60s.

[Accounts]
No account system, no sign-up. A server access token is optional and only used
to connect to the user's own instance. The app provides no AI generation
service, so it has no phone/ID real-name verification flow; access control
is enforced by the user's own server token.

[Permissions]
1. ohos.permission.INTERNET - reach the user-specified Harness service; the app's
core function is to render that service, so it cannot work without it.
(This is the only permission declared.)

[Data and privacy]
- No device identifiers, location, contacts or photos are collected.
- No data is sent to any third-party server; traffic flows only between the user's
device and the user's own server.
- No analytics, advertising or push SDKs.
- Server URL and access token are stored locally in app-private storage only.

[Third party / open source]
Open-source project (MIT), developer Zhou Tian. The mobile adaptation layer is
derived from an open-source project; see NOTICE.md in the repo for attribution.
Not affiliated with Huawei.

[Contact]
Developer: Zhou Tian
GitHub: https://github.com/cnzht/dsh-mobile-harmony
```
